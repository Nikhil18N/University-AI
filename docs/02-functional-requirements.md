# Functional Requirements

## Conversation
FR-001: User can start a conversation.
FR-002: User can send free-form text.
FR-003: Bot can respond to greetings.
FR-004: Bot can handle casual conversation.
FR-005: Bot can answer follow-up questions using conversation context.
FR-006: Bot asks clarification when a question is ambiguous.
FR-007: User can view conversation history.
FR-008: User can start a new conversation.

## University knowledge
FR-009: User can ask university-specific questions.
FR-010: System retrieves relevant university documents.
FR-011: Bot grounds university answers in retrieved evidence.
FR-012: Bot returns source references where applicable.
FR-013: Bot does not fabricate missing information.
FR-014: Admin can upload supported documents.
FR-015: Documents are processed, chunked, embedded and indexed.
FR-016: Admin can deactivate obsolete documents.

## Accounts
FR-017: User can authenticate.
FR-018: Authorized users can access their own conversations.
FR-019: Admin permissions are enforced server-side.

## Quality
FR-020: Errors are handled without exposing internal implementation details.
FR-021: User can submit feedback.
FR-022: System logs operational errors and latency without logging secrets.
